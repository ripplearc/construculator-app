# Build Flavors

The app has three build flavors: `fishfood`, `dogfood`, and `prod`.

Android, on the `env` dimension, differs only by `applicationId`:

| Flavor   | Android applicationId                    | iOS bundle id                            |
|----------|-------------------------------------------|-------------------------------------------|
| fishfood | `com.ripplearc.construculator.fishfood`  | `com.ripplearc.construculator.fishfood`  |
| dogfood  | `com.ripplearc.construculator.dogfood`   | `com.ripplearc.construculator.dogfood`   |
| prod     | `com.ripplearc.construculator`           | `com.ripplearc.construculator`           |

## How the flavors are defined

The flavor list lives in `pubspec.yaml` under the `flavorizr:` key and is
processed by the [`flutter_flavorizr`](https://pub.dev/packages/flutter_flavorizr)
dev dependency.

Running `dart run flutter_flavorizr -f` reads that config and writes the
generated files. The `instructions:` list in the `flavorizr:` config names the
exact processors that run. The default `flutter_flavorizr` run without that list
also rewrites `lib/main.dart` and generates Dart pages, which we do not want.

### Android

`dart run flutter_flavorizr -f` writes `android/app/flavorizr.gradle`. The last
lines of `android/app/build.gradle` apply it:

```
// ----- BEGIN flavorDimensions (autogenerated by flutter_flavorizr) -----
apply from: "flavorizr.gradle"
// ----- END flavorDimensions (autogenerated by flutter_flavorizr) -----
```

The generated `flavorizr.gradle` also declares a `string/app_name` resource per
flavor, set to the current launcher label `Construculator`. Nothing references
it: `android/app/src/main/AndroidManifest.xml` still uses the literal
`android:label="Construculator"`, so the displayed name is unchanged.

### iOS

`dart run flutter_flavorizr -f` also writes, for each flavor and each of Debug /
Release / Profile:

- `ios/Flutter/<flavor><Mode>.xcconfig` with `ASSET_PREFIX`, `BUNDLE_NAME`, and
  `BUNDLE_DISPLAY_NAME`.
- an Xcode build configuration `<Mode>-<flavor>` on the Runner target and the
  Runner project, based on the matching plain config, with
  `PRODUCT_BUNDLE_IDENTIFIER` set to the flavor bundle id.
- a shared scheme `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme`.

It also rewrites `ios/Runner/Info.plist` so `CFBundleDisplayName` reads
`$(BUNDLE_DISPLAY_NAME)` and `CFBundleName` reads `$(BUNDLE_NAME)`.
`BUNDLE_DISPLAY_NAME` is `Construculator` for every flavor; `BUNDLE_NAME` is
pinned to `construculator` so `CFBundleName` is unchanged.

`ios/Podfile` lists the `<Mode>-<flavor>` build configurations in its
`project 'Runner'` map so CocoaPods resolves the right base config per flavor.
Those entries are maintained by hand next to the plain three, not generated.

## Do not hand-edit generated flavor files

`android/app/flavorizr.gradle`, `ios/Flutter/<flavor><Mode>.xcconfig`, and the
generated schemes are produced by `flutter_flavorizr`. Do not edit them by hand.
To change a flavor, edit the `flavorizr:` block in `pubspec.yaml`, re-run
`dart run flutter_flavorizr -f`, then commit the changed files. The
`ios/Runner.xcodeproj/project.pbxproj` and `ios/Runner/Info.plist` changes are
also produced by that command.

## Building a flavor

Each flavor also has a `config/flavors/<flavor>.json` feature manifest (see
CA-925). Resolve it before building, so `flutter build` gets the
`--dart-define-from-file` it needs to set each `ENABLE_X` flag; skipping this
step falls back to that flag's default, which can ship a feature (or leave
one out) that the flavor's manifest says otherwise:

```
bash scripts/ci/resolve_build_features.sh fishfood
fvm flutter build apk --flavor fishfood --dart-define=ENVIRONMENT=dev  --dart-define-from-file=build/generated/flavors/fishfood.json

bash scripts/ci/resolve_build_features.sh dogfood
fvm flutter build apk --flavor dogfood  --dart-define=ENVIRONMENT=qa   --dart-define-from-file=build/generated/flavors/dogfood.json

bash scripts/ci/resolve_build_features.sh prod
fvm flutter build apk --flavor prod     --dart-define=ENVIRONMENT=prod --dart-define-from-file=build/generated/flavors/prod.json

fvm flutter build ios --flavor fishfood --dart-define=ENVIRONMENT=dev
fvm flutter build ios --flavor dogfood  --dart-define=ENVIRONMENT=qa
fvm flutter build ios --flavor prod     --dart-define=ENVIRONMENT=prod
```
